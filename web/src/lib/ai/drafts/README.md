# B2-03 입력·출력 검증 및 생성 fallback — 2026-11-22

이번 작업은 `docs/api.md` 4–5절의 입력·출력 검증과 생성 흐름을 준비하는 **로컬 개발 단계**다. `/api/drafts` HTTP 경계는 마련했지만 실제 AI 공급자, 서버 인증/접근, 음성 API, DB 저장은 미연결이다. 앱 route는 연결 전 401/503을 반환한다. #27 완료나 Production 기능으로 표시하지 않는다.

## 구현한 범위

- 17개 관찰 키, 현재 enum 및 명시적 null, revision, 대상 ID 형식, 실제 관찰 시각, 원문 길이를 검사한다. 시간대 없는 시각·잘못된 날짜·허용 오차 밖의 미래 관찰 시각·알 수 없는 키를 거절한다.
- 수분 사건량/일합계/18시 누적량, mL 0/null, KST 구간과 집계 완료 여부를 구분한다. 범주로 수치를 추정하거나 사건을 합산하지 않는다.
- 모든 항목을 정해진 한국어 문구로 표시한다. 미관찰·미확인·미실시·해당 없음·거부를 보존하며 이동 도움과 휘청거림 관찰을 구분한다.
- 확인된 추가 관찰 원문은 그대로 별도 표시한다. 텍스트에서 수치를 추출해 구조화 필드에 확정하지 않는다. 반환한 입력 snapshot은 호출자의 입력 객체를 수정하지 않는다.
- 미리보기는 `requires_confirmation: true`를 반환한다. 이 표시는 실제 사용자의 확인이나 저장 완료를 뜻하지 않는다.
- 원문 전체가 지원하는 짧은 관찰 문장으로 구성된 경우에만 명확한 모순을 검사한다. 식사량의 정확한 비율, 같은 관찰 시각의 단일 수분량, 통증·휘청거림의 유무, 17개 항목의 명시적 이름/선택값을 비교한다. 발견된 차이는 `DraftInputError`의 422 `VALIDATION_ERROR`와 해당 필드/원문 경로로 알린다. 어느 입력도 자동 수정하지 않는다.

## 원문 검사 예시와 한계

11/23 F2 리뷰 반영: 관찰 시각과 단일 수분 사건 시각에만 서버보다 최대 5분 빠른 기기 시계를 허용한다. 입력 시각을 서버 시각으로 덮거나 보정하지 않으며 날짜·초 이하 원본 정밀도를 보존한다. 초안 문장에서는 KST 초 단위까지만 표시하고 반올림하지 않는다. 집계 구간 시작/종료에는 오차를 적용하지 않으며, 18시 누적/하루 총량은 서버 시각에 실제 종료된 구간만 받는다. 미래 관찰을 무조건 허용하거나 미완료 집계를 완료로 바꾸는 예외가 아니다. 저장/비교 어댑터는 원본 관찰 시각을 사용하고 이 차이를 함께 검토해야 한다.

| 선택값과 원문 | 처리 |
|---|---|
| 점심 절반 / `점심 0% 섭취` | 식사량·원문 정정 요청, 미리보기 생성 중단 |
| 150mL 사건 / `물 0mL 섭취` | 같은 관찰 시각이면 수분량·원문 정정 요청 |
| 휘청거림 없음 / `보행 시 휘청거림 관찰됨` | 보행 관찰·원문 정정 요청 |
| 150mL 사건 / `물 0.15L 섭취` | 정확한 단위 환산 후 일치, 원문 자체는 변경하지 않음 |
| 점심 절반 / `아침 0% 섭취` | 다른 끼니이므로 비교하지 않고 검토 대상으로 남김 |
| 18시 누적 650mL / `물 150mL 섭취` | 사건/누적량을 비교하거나 합산하지 않음 |
| null·미확인 / 원문에만 있는 사실 | 구조화 필드를 채우지 않고 원문을 보존 |
| `어제 통증 있음. 물 0mL 섭취.` 등 시점·대상·인용·정정·조건이 붙은 문장 | 전체 원문을 자동 비교하지 않고 사람 검토 대상으로 남김 |

일반 한국어 의미 분석기가 아니다. **지원하지 않는 절이 하나라도 있으면 그 문맥이 나머지 절을 한정할 수 있으므로 원문 전체를 자동 비교에서 제외한다.** 예를 들어 다른 대상의 기록을 현재 대상과 잘못 비교하지 않도록 한다. 지원하는 문장에서도 수분 사건이 여러 개이면 어떤 것을 뜻하는지 고르거나 합산하지 않는다. 범주 `적음`과 mL 사이의 의학적 관계, `평소와 같음`과 휘청거림의 관계를 추정하지 않는다.

내부 `source_review`에는 비교한 절의 수와 자동 비교하지 않은 원문/절을 남긴다. 비교 성공이나 오류 없음은 원문의 정확성·완전성이 검증되었다는 뜻이 아니며, **언제나 원본과 선택값을 함께 사람이 확인해야 한다.** 이 메타데이터는 내부 미리보기 전용이며 아직 HTTP 계약에 추가하지 않았다. 이 단계는 LLM의 출력 검증을 대신하지 않는다.

`previewTemplateDraft(value, now)`는 내부 미리보기 함수이고 HTTP 성공 응답이 아니다. 실제 공급자 실패가 발생하지 않았으므로 `fallback_reason`을 만들어 붙이지 않는다. `now`는 이후 서버가 전달해야 한다.

## 생성 결과의 사실 보존 검사

`buildDraftFacts`가 관찰 시각, 17개 선택 항목, 보행 관찰, 수분 정량 정보의 **20개 항목**과 허용 문구를 만든다. null도 미관찰로 명시한다. `buildProviderRequest`는 이 목록과 대상 ID/revision을 전달하며 추가 관찰 원문은 공급자에게 보내지 않는다.

공급자 어댑터는 JSON을 파싱한 아래 구조를 반환해야 한다. 공개 API 요청/응답을 바꾸는 구조가 아니라 내부 어댑터 전용이다.

```ts
{ resident_id, input_revision, facts: [{ id, text }, /* 모든 20개 항목 */] }
```

`validateGeneratedDraft`는 같은 대상/revision, 모든 항목의 정확히 한 번 등장, 항목별 허용 문구를 검사한다. 숫자·단위·부정·미확인 상태·시각·집계 구간·집계 완료 여부가 달라지거나 진단/조언이 추가되면 거절한다. 출력 순서는 서버가 고정하며 추가 관찰 원문은 검증 후 **그대로** 붙인다. 알 수 없는 응답 키나 자유 서술 필드는 받지 않는다.

**이는 자유로운 한국어 요약의 의미를 검증하는 기능이 아니다.** 예를 들어 입력과 뜻이 같더라도 허용 목록에 없는 `점심은 절반 드셨습니다.`는 거절한다. 현재 공급자는 제한된 문구를 선택하는 역할만 하며, 자연스러운 자유 서술 생성은 구현하지 않았다. 허용 문구가 부족한 경우 문구와 검증 사례를 함께 확장해야 한다. 원문은 다시 쓰지 않으므로 그 안의 사실을 잃지 않지만, 지원하지 않는 원문 모순이나 원래 관찰의 진실성까지 확인하는 것은 아니다.

## 시간 제한과 오류 대체

`generateDraft(value, dependencies)`는 입력 검사 → 신뢰할 수 있는 서버의 대상 접근 확인 → 공급자 호출 → 출력 검사 → 사람 검토용 응답 순서로 동작한다.

| 상황 | 결과 |
|---|---|
| 허용된 사실/문구로 정상 응답 | `generation_mode: llm`, `fallback_reason: null` |
| 공급자 호출이 기본 10초 초과 | `generation_mode: template`, `fallback_reason: timeout` |
| 공급자 호출 실패 | `template` / `provider_error` |
| 누락·변경·추가 사실, 다른 revision, 잘못된 출력 구조 | `template` / `invalid_output` |
| 입력 오류·명확한 원문 모순 | 기존 400/422 오류; 공급자 호출하지 않음 |
| 인증/대상 접근 확인 실패 | 오류 그대로 전달; 템플릿 성공으로 숨기지 않음 |
| 공급자/접근 검증 설정 미준비 | 503 `DEPENDENCY_NOT_READY` |

모든 성공/대체 응답에는 계약의 대상 ID, 입력 revision, `requires_confirmation: true`, `b2-01-draft-3` 메타데이터가 있다. 공급자 오류의 원문은 반환하지 않는다. 시간 초과 시 abort 신호를 보내며, 취소를 무시한 어댑터의 늦은 성공/실패가 반환한 템플릿을 바꿀 수 없다. 실제 어댑터는 이 신호를 네트워크 요청까지 전달해야 한다. 설정한 시간 제한은 **공급자 호출**에 적용되며 인증/DB를 포함한 전체 HTTP 제한은 아니다.

서버에서 인증된 문맥을 사용하여 `authorizeResident`를 구현해야 한다. 테스트의 빈 접근 콜백이나 가짜 공급자를 앱에 사용하지 않는다. HTTP factory는 입력 검증 결과를 노출하기 전에 인증하고 예외를 공통 오류 형식으로 변환한다. 실제 인증 어댑터는 미연결이다. 모듈은 저장하지 않으며 실제 사용자 확인도 대신하지 않는다.

## F1 화면 연결을 위한 요청·검토 helper

`client-request.ts`와 `review-state.ts`는 **아직 화면에서 사용하지 않는** B2 준비 코드다. F1 PR #56의 컴포넌트나 B1 저장 코드는 수정하지 않았다. 브라우저에서 실행 가능한 순수 함수이며 서버 구현은 type으로만 참조한다. 원문·토큰·확인 상태를 localStorage에 저장하지 않는다.

- `requestDraft(input, accessToken, { signal })`: 같은 사이트의 `/api/drafts`에 고정된 POST를 보낸다. 입력은 복사하고 서버 응답의 대상/revision/계약 버전/생성 방식/확인 필수 표시를 검사한다. 리다이렉트를 거절하며 원시 오류 메시지나 토큰을 표시하지 않는다. 실패할 때 브라우저가 임의로 템플릿을 만들지 않는다.
- `createDraftReview(input)`: 아직 확인되지 않은 입력 상태를 만든다. 완성된 계약 형태를 사용하되 실제 값 검증은 서버가 수행한다. 날짜/정량 정보/미관찰 null을 기존 화면 값으로부터 임의 추정하지 않는다.
- `replaceDraftObservation(state, observation)`: 대상·시각·17개 선택값·수분·보행·원문 변경 시 **반드시** 호출한다. revision을 올리고 초안·확인·진행 중 요청을 무효화한다. 화면 밖에서 state 객체를 직접 수정하거나 revision을 재사용하지 않는다.
- `beginDraftRequest(state)`: 별도 요청표(ticket)와 입력 복사본을 만든다. 같은 revision에서 재시도해도 요청표가 달라 이전 응답이 최신 결과를 덮을 수 없다.
- `receiveDraft(currentState, request, response)` / `failDraftRequest(currentState, request, error)`: **await 이전의 오래된 state가 아니라 현재 state**에 적용한다. 요청표가 다르면 성공·실패 모두 무시한다. 실패 후에도 입력은 유지된다.
- `confirmDraft(state)`: 사람의 확인 클릭에서만 호출한다. 생성 중/실패/편집 상태에서는 확인하지 않는다. `getConfirmedDraftSnapshot(state)`는 확인된 동일 revision의 입력과 문장만 복사해서 제공한다.

F1 연결 순서:

1. 실제 관찰 DTO와 사용자 확인된 음성 원문을 하나의 상태로 관리한다. 원문만 바뀌어도 revision이 증가해야 한다. 현재 PR #56의 `selectedSummary`/이름/검토 flags만으로는 전체 DTO나 승인 snapshot을 전달할 수 없으므로 prop/callback을 F1과 맞춘다.
2. 녹음 시작 시 기존 확인을 무효화하고, 녹음/종료 처리 중에는 생성·확인·저장을 막는다. 마지막 음성 결과가 확정된 뒤 원문 변경을 반영한다. 이 helper는 마이크 상태를 관리하지 않는다.
3. 생성 클릭에서 `beginDraftRequest` 후 해당 복사본으로 `requestDraft`를 실행한다. AbortController는 화면이 소유하며 새 요청·입력 변경·초기화·화면 종료 시 이전 요청을 취소한다. ticket 검사도 계속 사용하여 취소를 무시한 응답을 버린다.
4. 응답은 최신 상태에 반영하고 원본과 초안을 함께 일반 텍스트로 표시한다. 템플릿도 `generation_mode`/`fallback_reason`에 맞게 표시하고 다시 확인받는다. 본문 직접 수정은 기본 계약에 없으므로 입력 수정→재생성→재확인으로 연결하거나 변경을 먼저 합의한다.
5. 저장 클릭 시 **그 시점의** `getConfirmedDraftSnapshot` 결과를 사용한다. 과거 snapshot을 따로 보관해 재사용하지 않는다. 이 객체는 인증된 저장이나 서버 확인 증명이 아니다. B1은 권한·입력·revision을 검증하고 실제 저장 성공 후에만 완료로 표시한다. 기존 평평한 `saveObservation()`에 이 객체를 그대로 넣거나 확인자/확인 시각을 클라이언트가 만들어 보내지 않는다.

성공 응답 검사도 모델 사실 검증이나 원문 정확성 확인을 대신하지 않는다. 아직 실제 React 화면·마이크·Supabase 저장에 연결하지 않았으므로 테스트 성공을 사용자 흐름 완료로 간주하지 않는다. 전체 HTTP/네트워크 대기와 취소 UI는 F1 연결 때 검증하며, 서버의 10초 제한은 공급자 호출에만 적용된다.

## 연결 전에 남은 작업

1. [#27 공급자 확인 질문](https://github.com/jaehjung0102/careit/issues/27#issuecomment-7059058399)에 따라 팀의 문장 생성·음성 서비스와 설정 방법을 확인한다. 개인 계정이나 다른 프로젝트의 키를 대체 사용하지 않는다.
2. 내부 어댑터 구조에 맞는 실제 공급자를 연결하고 JSON 파싱, 모델 응답, 취소 신호, 품질을 검증한다. 지원하지 않는 표현의 모순은 이 검사로 찾지 못하므로 원본·선택값·초안의 사람 검토를 유지한다.
3. B1과 서버 인증/대상 접근 검증을 연결하고, 설정 미준비는 503으로 처리한다. 템플릿으로 권한 오류를 숨기지 않는다.
4. `/api/drafts`의 준비된 HTTP factory에 실제 의존 서비스를 연결한다. 가짜 서비스를 사용한 요청/응답 시험은 통과했지만 실제 토큰·모델을 사용한 HTTP 성공 검증은 아직 남아 있다. 연결 경계는 `web/src/app/api/drafts/README.md`를 참고한다.
5. 준비된 client/review helper를 F1 #3과 연결한다. 원문 확인→초안 검토→입력 수정 시 revision 증가/재확인, 입력 보존, 늦은 응답 무시는 함수 수준에서 검증했으며 화면에서 별도 확인해야 한다.
6. 음성 파일 형식·상한·브라우저/기기·실패 흐름을 확정하고, 실제 저장 경로까지 별도로 검증한다.

## 로컬 검증

앱 의존성을 설치한 `web/`에서 기존 TypeScript와 Node 내장 테스트 도구를 사용한다. 새 의존성을 추가하지 않는다. 아래 임시 출력 폴더는 저장소 밖에 둔다.

```sh
build_dir=$(mktemp -d)
node node_modules/typescript/bin/tsc --strict --skipLibCheck --target ES2022 --module commonjs --moduleResolution node --esModuleInterop --rootDir src --outDir "$build_dir" src/lib/ai/drafts/_tests/*.ts src/app/api/drafts/_tests/*.ts
node --test "$build_dir/lib/ai/drafts/_tests/"*.test.js "$build_dir/app/api/drafts/_tests/"*.test.js
```

이 테스트는 가상의 입력과 가짜 공급자에 대한 내부 함수 검증이다. 변경/누락/추가 사실, 원문 보존, 동시 revision, 시간 초과·늦은 응답·공급자 실패와 권한 오류 분리, 클라이언트 요청 및 검토 상태 전이를 검사한다. 서비스 모델의 품질, 실제 마이크, 인증/RLS, 실제 화면 입력 보존, Production 동작 또는 전체 업무 시간은 검증하지 않는다.
