# B2-02 음성 입력 기술 검증 — 2026-11-17

**결론: 수정 가능한 음성 초안의 구현은 계속할 수 있다. 현재 결과로 음성을 검토 없이 자동 저장하면 안 된다.** 브라우저 녹음과 로컬 한국어 전사를 각각 시험했다. 11/21에는 실제 사람 1명의 Mac 마이크→전사→수동 수정도 확인했다(3-1절). AI 초안→저장의 전체 연결, 휴대폰 음성 검증은 아직 아니다.

이 폴더는 B2 담당 영역의 개발 실험이다. 앱에서 import하지 않으며 F1 화면, 공용 패키지, B1 DB 또는 B2-01 PR #40의 계약을 변경하지 않는다. 인식 엔진·배포 방식도 아직 팀 확정 전이다.

## 1. 무엇을 확인하는가

돌봄 기록은 문장이 자연스러운 것보다 숫자·단위·부정 표현·미확인·말한 정정이 보존되는 것이 중요하다. 예: `150mL`는 이번 섭취량이며 하루 총량이라고 추정하면 안 된다. `통증 미확인`은 `통증 없음`과 다르다.

권장 흐름:

```text
F1: 녹음/중지 또는 직접 입력
  → B2: 음성 변환 (실패/무음이면 재녹음·직접 입력)
  → F1: 사용자가 전사문 확인·수정
  → B2: 확인된 텍스트로 AI 초안 생성
  → F1: 사용자가 항목·숫자·단위·관찰 시각 확인
  → B1: 확인한 버전의 기록 저장
```

음성으로 인계가 자동 전송되거나 기록이 자동 저장되지 않는다. 사람의 검토를 생략하는 근거로 모델의 자신감 점수를 사용하지 않는다.

## 2. 이번에 실제 실행한 것

- multilingual `small`, CPU 4 threads, Apple Accelerate, Metal/GPU 미사용. 한국어 `ko`, 정답을 포함한 prompt 없음, 기본 decoding.
- 모델 SHA-1: `55356645c2b361a969dfd0ef2c5a50d530afd8d5` — upstream 표와 일치 확인.
- macOS `say`의 Yuna/Eddy 한국어 합성 음성, rate 170. 발화 6개(약 5.2~10.7초) + 정확한 디지털 무음 5초. 가상의 사례이며 실제 사람·시설 데이터 없음.
- WAV mono 16kHz PCM으로 변환 후 전사. 파일마다 CLI를 새로 실행.
- 실행 시간 **1.877~3.758초**, 발화 6개의 중앙값 **2.608초**. 모델 로딩과 전사 포함. 녹음 길이·업로드·사용자 수정·AI 초안·최종 저장 시간은 제외. 앱 반응 속도/전체 작성 시간이라고 주장할 수 없다.
- 첫 시도는 실행 제한 때문에 시스템 합성 음성이 빈 파일이 되어 발화 6개 전사가 실패했다. 점수에서 제외하고 음성 길이 검사를 추가했다. 접근 가능한 실행 환경에서 `voice-local-small-run2`를 다시 실행해 실제 비어 있지 않은 6개 음성을 검증했다.
- 외부 API 호출, API 키 사용, 녹음 업로드, 실제 마이크 접근 없음. 도구/모델만 임시 폴더로 다운로드했다.

## 3. 결과와 의미

| 사례 | 관찰한 결과 | 판단 |
|---|---|---|
| 점심 50%, 물 150mL, 휘청거림 없음 | 세 사실 보존 | 이 사례는 의미 보존 |
| 오후 3시, 휘청거림 있음, 직원 1명 도움 | 시간·휘청거림·직원 수 표현 훼손 | 수정 필요 |
| 물 섭취량·통증 여부 미확인 | 두 미확인 보존, 섭취량 철자 오류 | 의미 보존, 철자 교정 가능 |
| 이번 물 0mL, 하루 총량 미확인 | **0mL가 10mL로 바뀜**; 물을 권함이 끓임으로 바뀜 | 수정 필수 |
| 오전 9시 체온 36.5도, 통증 없음 | 숫자·부정은 보존하나 `체온`이 `채 오는`으로 바뀜 | 항목의 의미 불명확, 수정 필요 |
| 50mL라고 말한 뒤 150mL로 정정 | 두 숫자는 남지만 `아니`가 사라져 정정 관계 불명확 | 수정 필요 |
| 5초 무음 | `-감사합니다. -감사합니다.` 생성 | 무음 처리 실패 |

이 판단은 에이전트가 원문과 전사문을 비교한 초안이며 독립적인 원어민 평가가 아니다. 두 합성 음성이 서로 다른 사례를 읽었으므로 음성별 성능 비교도 아니다. 소수 합성 사례로 일반 정확도나 실제 종사자의 업무 절감률을 산출하지 않는다. `assessment.json`에 사실별 보존 여부와 판단 근거를 분리했다. 원문은 `local-results.json`에 있다.

브라우저 검증은 내장 Chromium 157의 localhost에서 수행했다. 생성한 1초 tone을 `audio/webm;codecs=opus`로 녹음하여 14,786 bytes, 약 0.9초로 decode했다. 마이크/API 존재도 확인했으나 마이크 권한·실제 음성 인식 작동을 증명한 것은 아니다. MP4는 지원 응답만 확인했고 실제 녹음은 WebM 하나만 했다. Safari/iPhone/Android는 미검증이다. `browser-result.json` 참고.

## 3-1. 2026-11-21 실제 마이크와 수동 수정 — 단일 가상 사례

별도 로컬 실험 페이지에서 Chrome/Mac 마이크로 아래 지정 문장을 읽고, 중지 후 전사문을 확인했다. 앱의 Production 기능이나 실제 어르신 기록을 사용한 시험은 아니다. 원문/수정문과 판단은 `human-microphone-result-20261121.json`에 기록했다.

- 지정 문장: `점심은 오십 퍼센트 드셨고, 물은 백오십 밀리리터 드셨습니다. 보행 시 휘청거림은 없었습니다.`
- 실제 화면의 원본 전사: `점심은 50% 더 되셨고 물은 150ml 더 되셨습니다. 보행 시 휘정 거림은 없었습니다.`
- 사용자가 수정한 후 직접 확인한 문장: `점심은 50% 드셨고, 물은 150mL 드셨습니다. 보행 시 휘청거림은 없었습니다.`
- 화면 표시 녹음 길이 14.16초, 로컬 처리 1.49초. 검토·수정·AI 생성·최종 저장 시간은 포함하지 않으며 수정 시간은 측정하지 않았다.
- 50%, 150mL와 부정 표현 `없었습니다`는 보존됐다. 섭취 동사가 `더 되셨...`로 변하고 `휘청거림`이 `휘정 거림`으로 인식되어 **원본은 수정이 필요했다**. 세 문장이 오류 없이 인식됐다고 채점하지 않는다.
- 사용자에게 수정할 참고 문장을 제공했다. 따라서 이번 확인은 **녹음→전사→직접 편집 가능 여부**이며, 독립적인 사용성/정확도 평가나 오류 원인 분석이 아니다. 발음만의 문제라고 단정하지 않는다.
- 성공 표시는 `YOUR MICROPHONE`과 전사 결과를 직접 읽어 확인했다. 임시 음성은 실험 서버에서 삭제하며 결과 확인 시 원본 녹음을 다시 듣지 않았다. 저장소에는 음성 파일과 개인 경로/계정 토큰을 포함하지 않는다.
- 별도 로컬 서버의 45초 상한·오류 처리 등은 이 단일 성공 사례로 모두 검증한 것으로 간주하지 않는다. 테스트용 서버는 앱/Production에 통합되지 않았다.

이 결과는 편집 가능한 음성 초안과 사람의 검토를 유지하는 방향을 뒷받침한다. 한 명·한 문장·한 기기의 결과로 일반 인식률, 한국어 억양별 성능, 모바일 성공이나 업무 시간 절감률을 주장하지 않는다.

## 4. 구현 선택

| 선택 | 장점/제약 | 이번 판단 |
|---|---|---|
| 브라우저 SpeechRecognition | 빠른 UI 실험 가능. 브라우저 지원이 제한되고 일부 구현은 외부 서비스로 음성을 전송 | 유일한 기본 경로로 의존하지 않는 것을 권장. 이 실험에서는 호출하지 않음 |
| MediaRecorder + 서버 음성 인식 | 녹음·변환·검토를 분리하고 인식 엔진을 바꿀 수 있음. 서버와 파일 형식 처리가 필요 | **권장 구조**, F1/B2 연결 계약에서 확정할 제안 |
| 로컬 whisper.cpp | 이번 CPU 시험은 실행 가능, API 키 불필요. 모델·프로세스 운영 필요하고 의미 오류 발견 | 로컬 실험 기준선. 운영 엔진으로 확정하지 않음 |

브라우저는 HTTPS(개발 시 localhost)와 마이크 허용이 필요하다. MIME은 기기에서 실제 지원하는 형식으로 선택한다. WebM/Opus만 강제하지 않는다. 브라우저 형식을 서버가 검증·decode하여 인식 엔진 입력으로 변환해야 하며, 이번 전사 시험은 WAV만 사용했으므로 **브라우저 파일→서버 전사 연결은 별도 검증**이다.

서버에 로컬 Whisper를 배포하려면 모델 크기·메모리·프로세스·실행 제한을 먼저 확인해야 한다. 이번 Mac의 속도로 배포 환경의 속도를 추정하지 않는다. 외부 음성 API 비교는 비용·키·오디오 전송 대상 합의 후 같은 사례로 실행한다. 이번 작업은 API 선택/접속을 하지 않았다.

## 5. B2-03 (#27)에서 이어갈 순서

1. F1과 녹음 파일 형식, 길이/크기 상한, 변환 요청·응답·오류, 사용 브라우저를 합의한다. F1 화면은 수정하지 않았으며 이 문서가 확정 API 계약을 대신하지 않는다.
2. 빈 파일·너무 짧은 파일·무음을 변환 전에 검사하고, 음성 구간 감지 및 사용 가능한 전사문이 없는 경우의 오류 처리를 추가한다. 이번의 무음 생성 오류를 회귀 사례로 유지한다. 감지기를 추가했다고 모든 허위 전사가 사라졌다고 간주하지 않는다.
3. 변환 중·실패·재시도·직접 입력 흐름을 연결한다. 실패해도 기존 타이핑/버튼 입력과 수정 내용을 유지하고, 재시도가 중복 저장을 만들지 않게 한다.
4. 전사문을 먼저 수정·확인하게 하고 그 텍스트에서 초안을 생성한다. 초안 이후 입력이 바뀌면 재생성·재검토가 필요하다. 숫자나 부정 표현을 추측으로 자동 교정하지 않는다.
5. 동의한 팀원들이 가상 사례를 실제로 읽어 시험한다. 데스크톱/휴대폰, 조용한 곳/배경 소음, 마이크 거부, 빈 음성, 통신/변환 실패를 확인한다. 이 단계 전에는 실제 어르신 기록을 쓰지 않는다.
6. 최종 사용성 시험에서는 제안서 기준대로 **사례 제시→검토·수정→최종 제출** 시간을 측정한다. 음성 처리·AI 대기 포함. 필수 사실 반영률, 숫자·단위·부정 오류, 추가 사실, 도움 요청/완료 여부를 별도 기록한다. 이번 전사 실험 시간을 그대로 최종 작성 시간으로 쓰지 않는다.

11/20 범위 확인: B2-02의 초기 음성 기술 검증 자료는 PR #41로 병합되었다. 11/18 팀 계획에 따른 #26의 남은 종료 조건은 #25 합의 반영, F2 리뷰, 제한·검증 결과 기록이다. 실제 엔진 선택·전체 음성 흐름·B1 연결은 #27 및 후속 통합에서 계속한다. 실제 사람 1명의 Mac 마이크·전사·참고 문장에 따른 수동 편집은 3-1절에서 확인했다. 휴대폰 음성·다양한 사례·전체 저장 흐름은 여전히 미검증이며, 앱을 휴대폰에서 열어 본 사실만으로 마이크 검증 완료를 주장하지 않는다.

## 재현

앱 의존성 변경 없이 Python 표준 라이브러리로 실행한다. `say`는 macOS 전용이며 해당 한국어 음성이 설치되어 있어야 한다. ffmpeg와 따로 빌드한 whisper.cpp CLI/모델이 필요하다. 출력 폴더가 비어 있지 않으면 기존 근거를 보호하기 위해 중단한다.

```sh
python3 run_local.py --whisper-cli /path/to/whisper-cli --model /path/to/ggml-small.bin --output /path/to/new-run
```

별도 임시 clone에서 v1.9.5, CMake 4.2.3으로 `-DCMAKE_BUILD_TYPE=Release -DGGML_METAL=OFF -DWHISPER_BUILD_TESTS=OFF -DWHISPER_BUILD_SERVER=OFF`를 설정하고 `whisper-cli` target을 빌드했다. CLI 실행 옵션은 스크립트에 있다. 합성음·모델·빌드 도구는 저장소에 포함하지 않는다.

브라우저 시험은 이 폴더를 로컬 정적 서버로 열고 `browser-probe.html`의 **Test synthetic recording**을 누른다. 이 페이지는 마이크를 열지 않고 외부 전송도 하지 않는다. `browser-result.json`은 2026-11-17의 관찰 결과이며 매 실행 크기/시간은 달라질 수 있다.
